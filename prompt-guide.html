PART 01 · 프롬프트 작성법무엇을 · 왜 · 어떻게로 업무 요청하기

프롬프트는 AI에게 전달하는 업무 요청입니다

AI가 스스로 알 수 없는 우리의 ‘업무 맥락’을 함께 제공합니다

Before “이 자료 잘 정리해줘”
After “이 목적에 맞게, 이 자료로, 이런 결과를 만들어줘”

1. 목표를 공유

같은 원문 자료라도 읽는 독자와 활용 목적에 따라 강조해야 할 포인트가 완전히 바뀝니다.

2. 조건을 명시

사용할 자료의 한계, 제외할 범위, 표나 글머리 기호 같은 결과 형식을 명확히 정합니다.

3. 확인 기준을 설정

근거 문장 표시나 미확인 정보 표기 등 무엇을 통과해야 실무에 쓸 수 있는지 정합니다.

세 질문으로 요청을 구성합니다

무엇을 (What) → 왜 (Why) → 어떻게 (How)

무엇을 WHAT

수행할 일과 받을 산출물

동사 + 대상 + 결과
작성 예시 “회의 메모에서 후속 실행 목록을 만들어 주세요.”
왜 WHY

사용 목적과 결과를 읽을 사람

목적 + 독자 + 상황
작성 예시 “팀장이 다음 회의에서 진행 상황을 점검하려고 합니다.”
어떻게 HOW

사용 자료와 작성·확인 조건

자료 + 형식 + 제약 + 완료 기준
작성 예시 “담당자·기한을 표로 쓰고 없는 정보는 ‘확인 필요’로 표시해 주세요.”

항상 [무엇을], [왜], [어떻게]라는 제목을 붙일 필요는 없습니다. 세 질문의 답이 요청 문장 안에 자연스럽게 들어 있는지 확인하세요.

05 · 무엇을 (What)
PART 01 · 프롬프트 작성법무엇을 · 왜 · 어떻게로 업무 요청하기

“분석해줘”를 구체적인 산출물로 바꿉니다

수행할 업무 동사와 결과물의 범위를 명확히 정합니다

모호한 요청
구체적인 산출물 요청 (동사 + 대상 + 결과)
“자료 좀 봐줘” 제공한 자료 두 건의 차이와 확인할 쟁점을 표로 비교해 주세요.
“회의 준비해줘” 회의에서 결정할 안건 3개와 안건별 확인 질문을 작성해 주세요.
“직원 코칭 자료 만들어줘” 가상 업무 사례에 대한 피드백 대화 초안을 작성해 주세요.

확인 질문: AI로부터 결과를 받았을 때, “내가 요청한 일이 끝났다”고 즉시 판단할 수 있나요?

06 · 왜 (Why)
PART 01 · 프롬프트 작성법무엇을 · 왜 · 어떻게로 업무 요청하기

목적을 알려주면 요약의 기준이 생깁니다

같은 자료라도 읽는 독자와 의사결정에 따라 선별 기준이 달라집니다

사용 목적 요청에 추가할 설명 (독자 + 판단 기준)
경영회의 의제 선정 “경영진이 우선 검토할 쟁점을 고르기 위한 자료입니다. 영향과 불확실성을 중심으로 정리해 주세요.”
팀 업무 점검 “팀장이 후속 조치를 확인할 자료입니다. 담당자와 기한, 미결사항을 중심으로 정리해 주세요.”
직원 피드백 준비 “직원이 다음 행동을 정하도록 돕는 대화 초안입니다. 관찰 사실과 제안을 구분해 주세요.”

여기서 “왜”는 AI의 내부 사고 과정을 캐묻는 말이 아니라, 이 결과를 실무 어디에 사용할지 알려주는 맥락 설명입니다.

07 · 어떻게 (How)
PART 01 · 프롬프트 작성법무엇을 · 왜 · 어떻게로 업무 요청하기

자료·형식·제약·완료 기준을 정합니다

중요한 조건부터 짧고 명확하게 전달합니다

어떤 자료로? (근거 제약)

제공한 회의 메모만 사용합니다. 자료에 없는 사실은 임의로 만들지 않습니다.

어떤 형태로? (출력 형식)

결정사항 · 후속조치 · 담당자 · 기한을 한눈에 볼 수 있도록 표로 작성합니다.

어디까지 확인? (완료 기준)

메모에 없는 담당자나 기한은 “확인 필요”로 표시하고, 각 항목에 근거 문장을 붙입니다.

최신 모델 활용의 핵심: 목표와 제약, 결과 기준을 분명히 하되 불필요하게 모든 중간 사고 과정을 지시하지 않습니다.

08 · 작성 습관
PART 01 · 프롬프트 작성법무엇을 · 왜 · 어떻게로 업무 요청하기

긴 역할 설정보다 업무 조건을 구체화합니다

기존의 상투적인 프롬프트 습관을 실무 요청으로 다듬기

흔히 쓰던 습관적 표현 더 유용한 실무 작성 방법
“당신은 20년 경력의 최고 전문가입니다.” 필요한 검토 관점을 명시합니다.
예: 팀 업무 점검 관점에서 누락된 담당자와 기한을 찾아 주세요.
“단계별로 자세히 생각해 주세요.” 결과에 필요한 근거와 확인 사항을 요청합니다.
예: 각 제안의 원문 근거와 전제 가정을 함께 써 주세요.
“무조건 질문부터 해 주세요.” 핵심 결측치와 일반 누락 처리 방식을 구분합니다.
예: 결과가 크게 달라질 핵심 정보가 없으면 질문하고, 나머지 누락은 ‘확인 필요’로 표시하세요.
“알아서 완벽하게 해 주세요.” 구체적인 완료 기준을 씁니다.
예: 모든 후속조치에 담당자·기한 또는 ‘확인 필요’가 빠짐없이 표시되어야 합니다.

역할, 과업, 맥락, 출력 형식은 여전히 유용한 점검 요소입니다. 세 가지 질문(무엇을·왜·어떻게) 안에 필요한 요소를 담으면 됩니다.

가상 회의 메모로 요청을 작성해 봅니다

아래 원문 자료를 AI에 제공한다고 가정합니다

가상 팀 회의 메모
원문 데이터 (Input) 
· 업무 요청이 이메일과 메신저로 나뉘어 들어와 누락 여부를 확인하기 어렵다는 의견이 나왔다.
· 김 담당자가 공통 요청 양식 초안을 다음 회의까지 작성하기로 했다.
· 요청 현황을 한곳에서 관리하는 방안은 검토하기로 했으나 담당자는 정하지 않았다.
· 개선 효과를 어떤 지표로 확인할지는 다음 회의에서 논의하기로 했다.
포인트 1 · 확정된 실행 김 담당자 / 양식 초안 / 다음 회의까지
포인트 2 · 미확정(검토) 통합 관리 방안은 ‘검토’ 단계이며 담당자 미정
포인트 3 · 차기 논의 개선 효과 지표는 다음 회의 안건

위 메모는 교육을 위한 가상 인물·가상 상황이며 실제 유안타증권의 업무 현황을 나타내지 않습니다.

실습 프롬프트
[무엇을] 가상 후속조치 6건을 사용하는 팀 업무 점검 보드를 단일 HTML 파일로 만들어 주세요. 항목·담당자·기한·상태를 표로 표시하고, 상태 필터와 담당자 검색 기능을 넣어 주세요.
[왜] 팀장이 회의에서 미결사항과 다음 행동을 점검할 시제품입니다. 실제 고객·거래 정보는 사용하지 않습니다.
[어떻게] 가상 데이터임을 표시하고 상태는 진행·완료·확인 필요로 구분하세요. 기한이 없는 항목 1건을 포함하고 “확인 필요”로 표시하세요. 검색 결과가 없으면 안내 문구를 보여 주세요. CSS와 JavaScript를 파일 안에 포함하고 외부 라이브러리·폰트·API 호출 없이 동작하게 하세요.
[완료 기준] 필터와 검색을 함께 적용할 수 있고, 조건을 초기화하면 전체 6건이 다시 보여야 합니다. 완성된 HTML 파일 또는 생략 없는 전체 코드를 제공하고 실행 방법을 안내해 주세요.

① 파일로 저장

AI가 제공한 HTML 파일을 내려받거나, 전체 코드를 텍스트 편집기에 붙여 넣어 UTF-8의 업무점검.html로 저장합니다. 확장자가 .txt인지 확인합니다.

② 브라우저에서 열기

저장한 파일을 Chrome 또는 Edge로 엽니다. 가상 데이터 6건과 지정한 항목이 보이는지 확인합니다.

③ 조건을 바꿔 보기

상태와 담당자를 함께 선택하고, 없는 담당자를 검색해 봅니다. 초기화 후 6건이 복원되는지 확인합니다.
